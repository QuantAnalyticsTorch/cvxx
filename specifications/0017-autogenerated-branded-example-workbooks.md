## Objective

Replace the single hand-built `docs/examples/Introduction.xlsx` with a
small library of example workbooks, one per major area of `cvxx`
functionality, produced by a new Rust generator program rather than
maintained by hand in Excel. Every generated workbook shares one visual
theme (blue headers/accents on a white background) so the set reads as one
consistent, professionally branded product, and every workbook explains in
plain language the business problem it illustrates before showing the
formulas and the solved answer. The generator runs as a packaging step
(`scripts/package-release.ps1`) and as a CI validation step, so
`docs/examples/` is always reproducible from source and cannot silently
drift from the current `CVX.*` function surface.

Workbooks produced (each a separate `.xlsx` file in `docs/examples/`,
discovered automatically by the existing ribbon Examples gallery
described in [modRibbon.bas](C:/Home/Github/cvxx/xlam/source/modRibbon.bas),
which lists every `*.xls*` file in that folder — no change to that
mechanism is required):

| File | Area covered | Business scenario |
|---|---|---|
| `01-parameters-and-variables.xlsx` | `CVX.PARAMETER`, `CVX.VARIABLE`, `CVX.DESCRIBE`/`CVX.SHAPE`/`CVX.TYPE` | A household's known monthly expenses (parameter) alongside unknown savings targets (variables) |
| `02-expressions.xlsx` | `CVX.EXPRESSION`, `CVX.ADD`/`CVX.SUB`/`CVX.MUL`/`CVX.DIV`/`CVX.NEG`/`CVX.SUM`/`CVX.SCALE` | A markup-pricing calculator that builds a total-revenue formula from unit price and quantity variables |
| `03-constraints.xlsx` | `CVX.CONSTRAINT`, `CVX.LESS_THAN`/`CVX.GREATER_THAN`/`CVX.EQUAL`, `CVX.CONSTRAINTS` | A factory's production limits expressed as a checklist of capacity and demand constraints |
| `04-problems-and-solving.xlsx` | `CVX.MINIMIZE`/`CVX.MAXIMIZE`, `CVX.PROBLEM`, `CVX.SOLVE` | The classic diet problem: minimize weekly grocery cost subject to nutrition constraints |
| `05-quadratic-problems.xlsx` | Quadratic objectives/constraints (SPEC-0011, SPEC-0016), `CVX.MATMUL`/`CVX.TRANSPOSE` | Portfolio risk minimization: choose asset weights that minimize `x.T @ sigma @ x` subject to a target return and a fully-invested constraint, consistent with the "portfolio risk" running example in SPEC-0016 |
| `06-vector-matrix-indexing.xlsx` | `CVX.INDEX` / `index(...)` | Selecting individual line items or sub-ranges out of a multi-period budget vector/matrix |
| `07-inspecting-results.xlsx` | `CVX.VALUE`, `CVX.STATUS`, `CVX.OBJECTIVE_VALUE`, `CVX.DESCRIBE`/`CVX.SHAPE`/`CVX.TYPE` | Re-examining the diet-problem result from `04-problems-and-solving.xlsx`: reading back status, cost, and quantities, and describing the handles involved |

`00-overview.xlsx` is also generated as a short, brand-forward landing
sheet (title, one-paragraph description of `cvxx`, and a table of contents
listing the other six workbooks by file name and scenario) — it has no
`CVX.*` formulas of its own and exists purely to give the Examples gallery
a sensible first entry.

## Non-Objective

- No `CVX.LP_SOLVE`/`CVX.QP_SOLVE`/`CVX.LEAST_SQUARES` example workbook.
  ISSUE-0008's one-shot convenience solvers are still in `draft` status
  with no implementation in [src/excel/mod.rs](C:/Home/Github/cvxx/src/excel/mod.rs)
  (only the 28 functions registered there exist today). Generating an
  example for functions that do not exist is out of scope; when ISSUE-0008
  is implemented, a follow-up specification adds an
  `08-convenience-solvers.xlsx` generator function alongside the others
  defined here, reusing the same theme module and packaging step.
- No changes to the ribbon XML, `modRibbon.bas`, or the Examples gallery
  discovery mechanism — it already lists every `*.xls*` file in
  `docs/examples/` with no manifest to update.
- No change to `docs/*.md`/`docs/html` content or styling beyond sharing
  the same blue/white hex palette (defined once below) so the examples and
  the rendered docs feel like one product; this spec does not add custom
  `mdbook` CSS.
- No macros, VBA, or external links/images inside the generated
  workbooks — plain formulas and static formatting only, consistent with
  the offline, no-network-call constraint already established for
  `docs/html` in SPEC-0001.
- No attempt to pre-compute and cache correct formula results inside the
  `.xlsx` file itself (the generator does not evaluate `cvxrust`); see
  Error Handling for how recalculation-on-open is handled instead.
- No 32-bit Excel, localization, or non-English content.

## Interface

### New workspace member: `tools/gen-examples`

A new Cargo workspace member, `tools/gen-examples`, added to the
`[workspace] members` list in [Cargo.toml](C:/Home/Github/cvxx/Cargo.toml)
alongside `cvxrust`. It is a standalone binary crate (`gen-examples`) that:

- Depends on [`rust_xlsxwriter`](https://crates.io/crates/rust_xlsxwriter)
  (pure Rust, no Excel/COM dependency, builds and runs on any OS including
  the `windows-latest` CI runner) to write `.xlsx` files directly, without
  needing Excel installed.
- Does **not** depend on `cvxx`, `xladd`, or `cvxrust`: it only writes
  formula *text* (e.g. `=CVX.SOLVE(C12)`) and static cell formatting, it
  never evaluates a problem. This keeps the generator a thin, pure-data
  tool, consistent with the layering principle that `cvxx`'s own crate
  stays free of unrelated dependencies.
- Is invoked as `cargo run -p gen-examples --release -- --out docs/examples`
  with no other required arguments; `--out` defaults to `docs/examples`
  relative to the workspace root when omitted.
- Exits non-zero and prints a diagnostic to stderr if `--out` cannot be
  created or written to, or if any workbook fails to build.

### Module layout

```
tools/gen-examples/
  Cargo.toml
  src/
    main.rs        -- CLI entry point: parses --out, calls each workbook
                       builder, fails loudly on any error
    theme.rs        -- shared blue/white style: fonts, fills, borders,
                       column widths, freeze panes, used by every workbook
    scenario.rs      -- shared helpers for the repeated "title block" /
                       "narrative paragraph" / "formula + result" layout
                       pattern every workbook follows
    workbooks/
      overview.rs
      parameters_and_variables.rs
      expressions.rs
      constraints.rs
      problems_and_solving.rs
      quadratic_problems.rs
      vector_matrix_indexing.rs
      inspecting_results.rs
```

Each `workbooks/*.rs` file exposes one function,
`pub fn build(path: &Path) -> Result<(), GenError>`, that constructs one
`.xlsx` file end-to-end (narrative sheet content + formulas + formatting)
and saves it to `path`. `main.rs` calls all eight in sequence and reports
every failure before exiting (it does not stop at the first error),
so a single broken workbook definition does not hide problems in the
others.

### Shared visual theme (`theme.rs`)

A single `Theme` struct defines the palette used by every workbook, so the
set is visually consistent and the palette is defined in exactly one
place:

| Element | Fill | Font | Notes |
|---|---|---|---|
| Workbook title (row 1) | `#1F4E78` (dark blue) | White, bold, 16pt | Merged across the sheet's used width |
| Section/narrative text | `#FFFFFF` (white) | Black, 11pt, wrapped | Plain prose explaining the scenario |
| Column headers | `#2E74B5` (mid blue) | White, bold, 11pt | Above each formula table |
| Input cells (parameters/knowns) | `#DCE6F1` (pale blue) | Black, 11pt | Numeric literals the user could edit |
| Formula cells (`CVX.*` calls) | `#FFFFFF` (white) | Black, 11pt, monospace-style (Consolas) | The formula text is visible in the formula bar; the cell shows Excel's computed value |
| Result/answer cells | `#EAF1FB` (very pale blue) fill, `#2E74B5` border | Black, bold, 11pt | The final solved value(s) the scenario is building toward |

`theme.rs` exposes one `rust_xlsxwriter::Format` constant/builder per row
in the table above (`Theme::title()`, `Theme::narrative()`,
`Theme::header()`, `Theme::input()`, `Theme::formula()`,
`Theme::result()`), plus shared layout constants: a fixed title-row
height, a 2-row narrative block with wrapped text and a set row height,
freeze panes below the narrative block (`worksheet.set_freeze_panes`), and
a default column width wide enough for a full `CVX.*` formula to be
readable without resizing.

These same six hex colors are recorded in a short new subsection of
[docs/architecture.md](C:/Home/Github/cvxx/docs/architecture.md) (an
architect-note style entry, per that file's existing format) titled
"Example workbook and documentation color palette", both so a future
`mdbook` custom-CSS pass can reuse them for `docs/html` (per ISSUE-0017's
note to align with the existing HTML documentation styling) and so this
spec's palette has one canonical, cross-referenced source of truth instead
of being redefined if `docs/html` theming work happens later.

### Per-workbook content contract

Every workbook (except `00-overview.xlsx`) follows the same layout, built
with the shared `scenario.rs` helpers:

1. **Title row**: workbook's scenario name (e.g. "Diet Problem: Minimizing
   Weekly Grocery Cost").
2. **Narrative block** (2-6 wrapped rows): 2-4 sentences in plain,
   non-technical language stating the business problem, phrased so a
   non-technical reader understands what's being solved and why, before
   any formula is shown.
3. **Inputs table**: labeled input cells (pale blue) holding the known
   numeric data for the scenario (e.g. nutrition requirements, prices),
   entered as literal numbers, never formulas.
4. **Formula walkthrough**: one row per `CVX.*` call, each row showing: a
   short label (e.g. "Step 3 - declare the problem"), the formula itself
   in a formula-styled cell, and a one-line comment-style explanation
   in an adjacent narrative-styled cell. Steps are ordered exactly as a
   user would type them (parameter/variable creation first, then
   expressions, then constraints, then objective/problem/solve), so the
   sheet doubles as a readable, linear tutorial.
5. **Result block**: the final answer(s) — e.g. `CVX.STATUS`,
   `CVX.OBJECTIVE_VALUE`, and `CVX.VALUE` for each decision variable —
   in result-styled cells, with a one-line plain-language statement of
   what the number means (e.g. "Cheapest weekly grocery cost that still
   meets every nutrition requirement:").

`00-overview.xlsx` uses only the title row and narrative block styling
(no inputs/formula/result tables), followed by a table of contents listing
each other workbook's file name and one-line scenario description.

### Packaging and CI integration

- [scripts/package-release.ps1](C:/Home/Github/cvxx/scripts/package-release.ps1)
  gains a new step, run whenever `-SkipBuild` is not passed and
  immediately before the existing `Assert-NonEmptyDirectory` check for
  `docs/examples`: `cargo run -p gen-examples --release -- --out docs/examples`.
  This replaces hand-maintaining `Introduction.xlsx`: the generator
  overwrites every `NN-*.xlsx` file in `docs/examples/` on each run (it
  does not need to delete stale files from prior schemes, since this spec
  fixes the final file-name list once).
- [.github/workflows/release.yml](C:/Home/Github/cvxx/.github/workflows/release.yml)
  gains a step after `cargo test` and before the `mdbook` build:
  `cargo run -p gen-examples --release -- --out docs/examples`, followed
  by a check that `docs/examples` is non-empty and contains exactly the
  eight expected file names (new `scripts/check-examples-generated.ps1`,
  mirroring the style of `scripts/check-docs-links.ps1`), so CI fails if a
  workbook is missing or a generator panic silently produced zero files.
- `docs/examples/Introduction.xlsx` is deleted from the repository; it is
  superseded by `00-overview.xlsx` plus the per-area workbooks above.
  `docs/examples/` no longer contains any hand-maintained, committed
  binary workbook — every file under it is build output. Because
  generated `.xlsx` files are reproducible, deterministic build artifacts
  checked into a doc-only folder (mirroring how `docs/html` is already
  `mdbook`-generated and still committed for the release archive, per
  SPEC-0001), they continue to be committed so a plain `git clone` without
  running the generator still has working examples; `cargo run -p
  gen-examples` simply regenerates and overwrites them when the function
  surface changes.

## Data Model

Inputs to the generator are compile-time-constant Rust data embedded in
each `workbooks/*.rs` file (scenario text, input numbers, formula
strings, labels) — there is no external data file or network data source.
Output is eight `.xlsx` files with no VBA, macros, external links, or
images; only worksheet cells, `rust_xlsxwriter::Format` styling, column
widths, and freeze panes.

Formula cells are written via `rust_xlsxwriter::Worksheet::write_formula`
(or `write_formula_with_format`) using plain A1-style references within
the same sheet (e.g. a parameter's formula in `B12` referenced as `B12`
from a later constraint formula) — no cross-sheet or cross-workbook
references, no array-formula (`CSE`) syntax, since none of the documented
`CVX.*` functions require one.

## Error Handling

- `rust_xlsxwriter` writes formula cells with a cached value of `0` (its
  default), which Excel treats as stale until recalculated. Every
  generated workbook sets its calculation mode to force a full
  recalculation on open (`Workbook::set_calculation_mode` with
  `FullRecalcOnLoad`, or the closest equivalent `rust_xlsxwriter` exposes;
  if the installed version lacks a direct API, the generator sets the
  workbook's `fullCalcOnLoad` attribute by writing the calculation
  properties directly), so opening a workbook with `cvxx.xll` loaded
  shows live, correct results rather than stale zeros — matching the
  existing expectation (unchanged from `Introduction.xlsx`) that the
  add-in must be loaded for the formulas to evaluate; this is documented
  in a one-line note on every generated `00-overview.xlsx` landing sheet.
- If a formula in a workbook references a handle/name from a cell that was
  renamed or reordered during development, that is a generator bug: unit
  tests (below) catch it by asserting every formula string's referenced
  cell addresses exist within the same sheet.
- `main.rs` collects errors from all eight workbook builders rather than
  aborting on the first failure, prints every failure to stderr with the
  file name that failed, and exits non-zero if any failed; it exits 0 only
  if all eight workbooks were written successfully.
- `scripts/package-release.ps1` already fails loudly (per SPEC-0001) if
  `docs/examples` ends up missing or empty; this spec does not change that
  check, only adds the generation step before it runs.

## Test Approach

- Unit tests in `tools/gen-examples` (`cargo test -p gen-examples`):
  - Each `workbooks::*::build` function, called with a temp-directory
    path, succeeds and produces a non-empty, valid `.xlsx` (re-opened and
    parsed with `rust_xlsxwriter`'s own round-trip support or a minimal
    zip/XML sanity check — a `.xlsx` is a zip archive, so asserting it
    unzips and contains `xl/workbook.xml` is sufficient without needing a
    full XLSX-reading crate).
  - A test asserts the full set of generated file names in a temp
    directory matches exactly the eight names in the Interface table
    above (catches an accidentally-renamed or accidentally-dropped
    workbook).
  - A test scans every formula string embedded in the Rust source for
    `CVX.` prefixes and asserts each one appears in the current
    registration list in `src/excel/mod.rs` (a simple substring/regex
    check reading that file at test time) — this is the mechanism that
    satisfies ISSUE-0017's "cannot silently go stale as functions change"
    acceptance criterion: a renamed or removed `CVX.*` function fails this
    test instead of silently shipping a broken example formula.
  - A test asserts every input literal number referenced by label text
    (e.g. "nutrition requirement") is actually used in at least one
    formula in the same workbook (catches orphaned inputs left over from
    edits).
- Manual: run `cargo run -p gen-examples --release -- --out docs/examples`,
  open each of the eight workbooks in 64-bit Excel with `cvxx.xlam` and
  `cvxx.xll` loaded, and confirm: formulas recalculate to non-error,
  sensible values on open; the Examples gallery (ribbon) lists all eight
  by file name; visual styling (colors, fonts, freeze panes) matches the
  theme table across every workbook.
- CI (`release.yml`): after the new generation step, `check-examples-generated.ps1`
  asserts `docs/examples/` contains exactly the eight expected files and
  that `Introduction.xlsx` is absent.

## Dependencies

- SPEC-0001 (release pipeline): this spec's packaging/CI steps extend, but
  do not replace, `scripts/package-release.ps1` and `release.yml`'s
  existing `docs/examples` handling.
- SPEC-0011 / SPEC-0016 (quadratic problems, vector/matrix quadratic
  support): `05-quadratic-problems.xlsx`'s portfolio-risk scenario depends
  on the `x.T @ sigma @ x` capability those specifications implement.
- SPEC-0018 (matrix multiplication and transpose): `05-quadratic-problems.xlsx`
  and `06-vector-matrix-indexing.xlsx` use the `@`/`.T` grammar and
  `CVX.MATMUL`/`CVX.TRANSPOSE`/`CVX.INDEX` it documents.
- ISSUE-0008 (one-shot convenience solvers): explicitly deferred (see
  Non-Objective); not a blocking dependency for this specification.
- `rust_xlsxwriter` crate: new external dependency, added only to the new
  `tools/gen-examples` workspace member, not to `cvxx` or `cvxrust`.
- Existing ribbon Examples gallery (`xlam/source/customUI.xml`,
  `xlam/source/modRibbon.bas`): consumed as-is, no changes required.
